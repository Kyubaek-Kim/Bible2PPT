# Bible2PPT 서비스 설계 문서

이 문서는 지금까지 개발한 Bible2PPT의 전체 설계를 종합해 정리한 것입니다. 제품 목표, 계층
구조, 각 모듈의 책임, 데이터 흐름, 핵심 정책(본문 원문 무결성), 패키징/배포, 테스트 전략, 알려진
한계와 향후 확장(특히 macOS 이식) 지점을 다룹니다.

---

## 1. 제품 목적과 대상 사용자

- **목적**: 성경 구절을 골라 배경 이미지가 깔린 PowerPoint(`.pptx`) 슬라이드를 자동 생성한다.
- **대상 사용자**: 개발 지식이 없는 일반 사용자. 실행파일(`Bible2PPT.exe`)을 더블클릭해 바로 사용.
- **인프라 방침**: DB·서버 등 외부 인프라 없음. 로컬 JSON(번역본·정경·i18n·versification)과
  사용자 설정 파일만 사용한다.

## 2. 플랫폼 방침 (Windows 우선)

- 이번 릴리스의 **실제 동작 타깃은 Windows 전용**이다.
- 다만 **향후 macOS 이식이 대규모 수정 없이 가능하도록** OS 의존 코드(경로, 폴더 열기, 폰트 등록)를
  처음부터 전용 모듈(`core/paths.py`, `core/platform_util.py`)로 격리하고 macOS 분기를
  스텁/best-effort로 마련해 두었다.
- 빌드는 Windows PyInstaller `.exe`만 산출하되, `Bible2PPT.spec`은 데이터 수집을 OS 독립적으로
  두고 아이콘/번들 방식만 `sys.platform`으로 분기해 macOS `.app` 브랜치를 쉽게 켤 수 있게 했다.

## 3. 계층 구조

로직은 `core/`, 표현은 `ui/`에 둔다. **`core`는 Tkinter를 import하지 않으므로** 단위 테스트와
재사용이 쉽고, UI 프레임워크 교체에도 강건하다.

```
main.py            엔트리포인트(얇음): ui.app.run() 호출
core/
  paths.py         OS 독립 리소스/사용자 데이터 경로 (번들 리소스 vs 쓰기 가능 사용자 폴더 분리)
  platform_util.py 폴더 열기 · 파일 선택 표시 · 폰트 등록 등 OS 의존 동작 격리
  parser.py        구절 파싱·정규화 (직접 입력/드롭다운/장 넘김, 잘못된 범위 거부)
  bible.py         정경 책ID · 번역본 레지스트리 · 구절 범위 확장
  alignment.py     번역본 간 절 정렬 (표시 레이어 매핑, 본문 무수정)
  importer.py      사용자 성경 업로드 파싱/검증/등록
  ppt.py           슬라이드 엔진 (비율·폰트·페이지네이션·배경·교차 배치·레이아웃 override)
  image_util.py    배경 크롭/알림 (Pillow)
  fonts.py         번들 폰트 + 미리보기 지원
  i18n.py          UI 언어 테이블
  settings.py      설정 영속화
  generator.py     상위 오케스트레이션 (UI가 호출하는 단일 진입점)
ui/app.py          Tkinter GUI (App + ImportDialog + LayoutDialog)
data/              canon / bibles / i18n / versification / fonts / 기본 배경
scripts/           canon·번역본·아이콘 생성 스크립트
tests/             core 단위 테스트
```

## 4. 모듈별 책임

| 모듈 | 책임 |
|------|------|
| `paths` | 번들 리소스(`sys._MEIPASS` 기준)와 사용자 데이터(OS별 표준 폴더)를 명확히 구분. Windows `%APPDATA%\Bible2PPT`, macOS `~/Library/Application Support/Bible2PPT`, Linux `$XDG_DATA_HOME` 분기. 기본 출력은 사용자 문서 폴더. |
| `platform_util` | `open_folder`/`reveal_file`(폴더 열기·파일 선택), `register_font`(프로세스 전용 폰트 등록), `font_install_hint`. Windows 구현 + macOS/Linux best-effort. |
| `parser` | 자유 형식/드롭다운 입력을 `Reference`로 정규화. NFKC 정규화, 구분자 변형 통일, 풀네임/약자/선택 언어 책이름 인식. **잘못된 범위(끝<시작)·0 이하 장·절 거부.** |
| `bible` | 정경 책(`Book`), 번역본 메타(`TranslationMeta`)·본문 지연 로딩(`Translation`), 레지스트리(번들+사용자 병합), `expand_reference`로 구절 범위를 정경 좌표 목록으로 확장. |
| `alignment` | 기준 정경 절 체계에 맞춰 각 번역본 절을 **표시 레이어에서** 매핑. 밀림=매핑 정렬, 합본=`N-M` 라벨, 누락=마커. 절 묶음(`VerseBundle`)이 페이지네이션의 원자 단위. |
| `importer` | 사용자 `.txt`/`.json` 파싱 → 검토(`ImportReport`) → 등록. 인코딩 자동 감지. 본문 원문 보존. |
| `ppt` | `SlideStyle` 기반 슬라이드 렌더링, 페이지네이션+자동 축소, 내어쓰기, 배경, 레이아웃 override. |
| `image_util` | 배경 이미지 cover-crop 계획(픽셀+cm 알림)과 적용, 히스토리 보관. |
| `fonts` | 고정 큐레이션 글꼴 목록, 번들 폰트 등록, 미리보기용 시스템 폰트 조회. |
| `i18n` | UI 언어 문자열/책이름 테이블. 본문 번역본 선택과 **별개**. |
| `settings` | 사용자 설정 로컬 JSON 영속화(전방/후방 호환 로딩). |
| `generator` | UI가 부르는 단일 오케스트레이터. 파싱→확장→정렬→렌더→저장, 구절별 오류 수집. |

## 5. 데이터 흐름 (입력 구절 → PPTX)

```
사용자 입력(드롭다운 또는 직접 입력) + 제목
        │  ui.app._build_reference_text()
        ▼
generator.generate(passages, translation_codes, style, background, output_folder, mode, i18n)
        │
        ├─ parser.parse(text) ─────────────► Reference (검증: 양수·비역전 범위)
        ├─ bible.expand_reference(ref) ────► list[Coord]  (정경 좌표)
        ├─ alignment.build_bundles(coords) ► list[VerseBundle] (번역본 교차, 표시 매핑)
        │        └─ 비어 있으면 "해당 구절 없음" 오류로 보고 (빈 덱 방지)
        ├─ ppt.fit_body_style / paginate ──► 슬라이드별 페이지 (절 묶음 무분할)
        └─ ppt.render → ppt.save ──────────► <출력폴더>/<파일명>.pptx
```

- **개별 모드**: 구절마다 별도 `.pptx`.
- **통합 모드**: 모든 구절을 한 `.pptx`로.
- 구절 단위 예외는 `GenerationResult.errors`로 모아 UI가 안내창으로 표시하고, 나머지 구절은 계속
  생성한다(부분 실패 허용).

## 6. 번역본 레지스트리와 정경 스키마

- 정경 스키마: `(책ID, 장, 절)`. 책 메타는 `data/canon.json`(`Book`: id/order/testament/ko/en/약자).
- 번역본 본문은 `data/bibles/<코드>.json`에 `{"meta": {...}, "books": {책ID: {장: {절: "본문"}}}}`
  형태로 저장. 원문 텍스트는 그대로 보존.
- 레지스트리는 **번들 번역본 + 사용자 번역본**을 병합하며, 같은 코드는 사용자 것이 우선한다.
- 본문은 **지연 로딩**(필요 시 파일에서 읽음)으로 시작 비용을 낮춘다.
- 기본 번역본은 개역한글(KRV). 저작권 판본(개역개정 등)은 제외.

## 7. 사용자 업로드/검토/등록 워크플로

1. **업로드**: `.txt` 또는 `.json` 선택(파일 다이얼로그).
2. **파싱**: 형식 자동 감지 — txt(`창 1:1 본문`, `Genesis 1:1 text`, 탭/다중 공백), json(중첩
   `{"창":{"1":{"1":...}}}`, 평면 `{"창1:1":...}`, 행 배열 등).
3. **검토(`ImportReport`)**: 책/장/절 통계, 누락·중복·형식오류 라인, **정경과 절 개수가 다른 책 경고**.
   검토를 통과해야 등록 가능.
4. **등록**: 이름/언어/약자/code 지정 → `data/bibles/<코드>.json` 저장 + 레지스트리 등록 + 원본
   파일 보관 → 드롭다운 즉시 노출.

## 8. 본문 원문 무결성 정책 (절대 원칙)

- 정렬·정규화·파싱·전처리 등 **어떤 단계에서도 성경 본문 텍스트 원문을 수정/훼손하지 않는다.**
- 저장은 항상 원문 그대로. 절 번호 밀림/합침/누락은 **표시(display) 레이어의 매핑**으로만 처리한다.
- 정규화·파싱은 **구절 참조(reference) 문자열**에만 적용되며, 본문에는 적용하지 않는다.

## 9. 구절 파싱과 장 넘김 확장

- 정규화(`normalize_text`): NFKC, 범위 문자(`~`,`—` 등)→`-`, 장:절 문자→`:`, 공백 정리.
- 인식 예: `창세기 15:1-15`, `창 15 1 15`, `창15:1~15`, `Gen 15:1-15`, `1 Corinthians 13:4-7`,
  장 넘김 `창 1:23-2:5`, 전체 장 `창 15`.
- **강건성**: 끝이 시작보다 앞서는 범위, 0 이하의 장·절은 `ParseError`로 거부 → UI가 안내.
- `expand_reference`는 시작 절을 포함하고 장 경계를 이어 확장하며, 존재하지 않는 장/절은 건너뛴다.

## 10. 정렬과 versification

- 기준축: KJV/개역 계열 정경 절 체계(`data/versification/kjv.json`).
- 각 번역본의 원문 절번호를 기준 절로 매핑(텍스트 수정 없음).
- 밀림=매핑으로 정렬, 합본=`N-M` 라벨로 합쳐 노출(잘라내지 않음), 누락=`(해당 절 없음)`.
- 사용자 업로드 성경은 "기준 정경과 절 번호 동일" 가정으로 처리하되, 절 개수 불일치 책은 검토
  단계에서 경고.

## 11. 번역본 선택과 교차 배치

- 체크박스 다중 선택. `자주 사용`(favorite) 체크 시 체크 순서대로 상단 고정, 나머지는 `더보기`로 접힘.
- `책·장·절 기준 성경`(base) 라디오: **선택한 번역본 중에서만** 지정 가능. 역할은 (1) 장·절 드롭다운의
  절 개수 기준, (2) 교차 배치 순서의 맨 앞.
- 교차 배치: 같은 기준 절의 모든 번역본 텍스트를 한 묶음으로(기준본 1절 → 다른본 1절 → 기준본 2절 …).

## 12. 구절 목록과 생성 모드

- 구절+제목을 `담기`로 목록에 추가/삭제. 여러 구절을 한 번에 처리.
- 생성 방식(구절 목록 바로 아래): `구절별 개별 PPT` vs `1개 PPT 통합`.

## 13. 페이지네이션과 자동 축소

- **절 묶음(`VerseBundle`) 무분할**: 같은 기준 절의 모든 번역본은 한 슬라이드에 함께 놓인다.
- 폰트/크기/비율에 따라 슬라이드당 줄 수를 재계산(폰트 실제 줄높이 ≈1.2배 × 줄간격 1.3배).
- 절이 딱 맞지 않으면 본문 글자를 최대 `MAX_BODY_SHRINK_PT`(2pt)까지, `MIN_BODY_FONT_SIZE`(12pt)를
  하한으로 자동 축소.
- 제목이 가로를 넘치면 제목 크기를 자동 축소.
- **알려진 한계**: 한 절 묶음 자체가 슬라이드보다 큰 경우 해당 묶음은 단독 배치되며 아래로 넘칠 수
  있다(무분할 원칙 유지의 대가).

## 14. 슬라이드 렌더링 모델

- 비율→슬라이드 크기: `16:9`(13.333×7.5in), `4:3`(10×7.5in), `A4`(11.69×8.27in). 알 수 없는 값은
  `16:9`로 대체.
- 상단: 제목(있으면 굵게, 없으면 구간 정보가 대신) + 구간 정보(굵게).
- 본문: 절 번호 접두 + 절마다 줄바꿈, 장 변경 지점에 `<N장>` 마커.
- 내어쓰기: 절 번호만 왼쪽 컬럼에 두고 탭 정렬로 첫 줄·이어지는 줄 본문이 같은 위치에서 시작 →
  왼쪽 라인이 직선. 들여쓰기 폭은 구절 내 가장 긴 절 번호 기준 자동 계산.

## 15. 레이아웃 커스터마이징과 영속화

- `화면 구성 커스터마이징` 창(`LayoutDialog`): 제목·구절·본문 상자를 **이동(안쪽 드래그)** 하거나
  **크기 조절(모서리 흰 핸들 드래그 — 대각선 화살표 커서)** 하고, 제목·구절의 크기/굵기/활성화를 지정,
  `저장`/`초기화`.
- **드래그 처리 모델**: 포인터 이벤트(`<Button-1>`/`<B1-Motion>`/`<ButtonRelease-1>`/`<Motion>`)는
  개별 도형이 아니라 **캔버스 위젯 레벨**에 바인딩된다. 히트 테스트(`_hit`)가 좌표로 대상을
  판정하므로(모서리 핸들 우선, 그다음 상자 내부; 겹칠 때는 위에 그려진 본문 우선), 매 이동마다
  상자·핸들을 다시 그려도(`_redraw_overlay`) 드래그 이벤트 스트림이 끊기지 않는다. 이동량은
  **누름 시점 스냅샷 대비 절대 오프셋**으로 계산해 커서를 1:1로 따라간다(핸들 재생성으로 인한
  드리프트/“1픽셀만 움직임” 버그 방지). 핸들은 작게(`_HANDLE`) 그리되 클릭 허용 반경은 넉넉하게
  (`_GRAB`) 둔다.
- 캔버스 배경에는 현재 선택된 배경 이미지가 **20% 불투명도(=투명도 80%)** 로 흐리게 깔려, 상자·라벨
  가독성을 해치지 않으면서 실제 슬라이드 위 배치를 미리 본다. 메인 창에서 배경을 바꾸면 열려 있는
  커스터마이징 창의 배경도 즉시 갱신된다(`App._notify_background_changed`).
- 저장 좌표는 **분수 `[x, y, w, h]`**(슬라이드 대비 비율)로 저장 → 비율이 달라도 재사용 가능.
- `저장` 시점 이후 생성되는 PPT의 세 요소 **차지 영역**(위치+크기)에 반영되고, `초기화`로 기본 배치로 복원.
- 리사이즈된 영역은 그대로 렌더링 엔진의 기하로 흘러가, 기존 원칙이 **바뀐 영역 기준으로** 유지된다:
  본문 줄바꿈/앞라인 정렬(`wrap_line`·hanging indent), 슬라이드 밖 넘침 방지(`fit_pages`가 최소
  글자크기까지 축소, 불가하면 `PaginationError`), 제목이 상자 폭을 넘으면 자동 축소(`_fit_single_line_size`).
- **경고**: (a) 본문이 활성 헤더(제목/구절) 영역을 침범, (b) 본문 영역이 너무 좁아 최소 글자크기로도
  두 줄이 안 들어감, (c) 헤더 상자 높이가 글자 크기보다 작아 잘릴 수 있음 → 창 하단에 실시간 경고,
  `저장` 시 재확인. (넘침 자체는 엔진이 항상 막으므로 경고는 사전 안내 성격.)

## 16. 타이포그래피/폰트 처리

- 고정 큐레이션 목록(번들 OFL): **나눔스퀘어 그룹** `Light`/`Regular`/`Bold`(기본)/`ExtraBold`,
  **나눔고딕 그룹** `Light`/`Regular`/`Bold`/`ExtraBold`, 그리고 Windows 기본
  (`맑은 고딕`/`굴림`/`돋움`/`바탕`/`궁서`).
- 폰트 선택은 **패밀리명(name ID 1)** 으로 이뤄진다. `나눔고딕`/`나눔고딕 Bold`만 한 패밀리(`나눔고딕`)를
  공유(RIBBI)하여 Bold는 **볼드 비트**로 도달하고, 나머지 웨이트는 각기 독립 패밀리
  (`나눔고딕 Light`/`나눔고딕 ExtraBold`/`나눔스퀘어 Light`/`나눔스퀘어`/`나눔스퀘어 Bold`/`나눔스퀘어 ExtraBold`)라
  이름으로 직접 선택하며 볼드 비트를 추가하지 않는다(중복 굵기=fake-bold 방지). 이 규칙은
  `FontChoice.needs_bold_bit`가 인코딩한다.
- 번들 폰트는 재배포 가능(OFL)해 출력 재현성 확보. 미설치 시 미리보기는 프로세스 전용 등록 시도 후
  실패하면 설치 안내를 노출(미리보기는 근사치임을 명시).
- 본문 굵기는 폰트 자체 굵기와 별개로 체크박스로 토글 가능.

## 17. 배경 이미지 처리

- 기본 배경 `data/ppt배경.png`. 사용자 이미지 첨부/히스토리 재선택 가능.
- 비율 불일치 시 잘릴 양을 **픽셀+cm**로 알리고 확인을 받은 뒤 cover-crop으로 꽉 차게 적용(Pillow).

## 18. 설정 영속화와 사용자 데이터 위치

- `settings.py`가 OS별 사용자 데이터 폴더의 로컬 JSON에 저장: UI 언어, 선택/자주 사용 번역본, 기준
  번역본, 비율/글꼴/본문 크기/굵기, 생성 모드, 출력 폴더, 배경/히스토리, 레이아웃 상자 및 제목·구절
  타이포그래피.
- **로딩 강건성**: 알 수 없는 키는 무시, 없는 키는 기본값 → 필드 추가 후에도 구버전 설정 파일 호환.
  손상되어 파싱이 불가한 파일은 기본값으로 폴백. 또한 더 이상 유효하지 않은 글꼴 라벨은 시작 시
  기본 글꼴로 보정.
- **저장 강건성**: `Settings.save()`는 같은 폴더의 임시 파일에 먼저 쓰고 `os.replace`로 원자적으로
  교체한다. 쓰기 도중 크래시가 나도 잘린/손상된 `settings.json`이 남지 않아(사용자 설정 전체가 조용히
  초기화되는 사고 방지) 항상 이전 정상본이 보존된다.
- 위치: Windows `%APPDATA%\Bible2PPT`, macOS `~/Library/Application Support/Bible2PPT`, Linux
  `$XDG_DATA_HOME/Bible2PPT`. 사용자 번역본은 사용자 데이터 폴더 하위 `bibles/`.

## 19. i18n 동작

- UI 언어(표시)와 번역본 선택(본문)은 별개.
- 정경 책ID를 공통 키로, 언어별 `data/i18n/<lang>.json`에 UI 문자열/책이름을 둔다. 책이름은 canon
  테이블로 폴백하므로 새 언어는 `ui` 문자열만 번역해도 사용 가능.
- 기본 한국어/영어, 확장 가능.

## 20. 패키징과 배포

- `requirements.txt`(python-pptx, pillow, requests 등), `requirements-dev.txt`(pytest, ruff,
  pyinstaller 등).
- Windows PyInstaller: `pyinstaller Bible2PPT.spec` → `dist/Bible2PPT.exe`. `data/` 자산(번역본 JSON,
  i18n, versification, 번들 폰트, 기본 배경)을 번들 포함.
- spec은 데이터 수집을 OS 독립으로 두고 아이콘/번들만 `sys.platform`으로 분기 → macOS 브랜치 확장 용이.
- GitHub Actions 크로스 빌드/macOS `.app`/서명·공증은 이번 범위 밖.

## 21. 테스트 전략

- `tests/test_core.py`: 파서(변형/장 넘김/실패/**잘못된 범위 거부**), 범위 확장(시작 절 포함), 본문
  무결성(trailing space 보존), 교차 정렬(누락 마커), 페이지네이션·자동 축소·내어쓰기(슬라이드 XML
  검증), 레이아웃 override·요소별 타이포그래피·본문 굵기, 즐겨찾기 순서, 개별/통합 생성, **구절 없음
  보고**, 업로드(txt/json·CP949/EUC-KR/UTF-16/BOM).
- 린트: `ruff check .`. CI는 Python 3.10/3.12에서 실행.
- GUI는 헤드리스(xvfb) 스모크로 앱 구성·주요 상호작용을 확인.

## 22. 알려진 한계와 향후 확장

- **한 절 묶음이 슬라이드보다 큰 경우** 오버플로 가능(무분할 원칙 유지). 향후 축소 하한 완화 또는 묶음
  내 안전 분할 옵션 검토.
- 본문 배치는 근사 폭/줄높이 모델로 계산 → PowerPoint 실제 레이아웃과 미세 차이 가능.
- **macOS 이식**: `paths`/`platform_util`의 macOS 분기(경로/폴더 열기/폰트) 구현, spec의 `.app`
  브랜치, Font Book 안내 경로가 이미 격리되어 있어 최소 수정으로 확장 가능.
- 설정 저장은 이미 원자적(`os.replace`). 사용자 JSON/번역본 메타의 스키마 검증, 등록된 번역본
  JSON의 원자적 쓰기, SBLGNT/Nestle1904 어댑터는 향후 강화 지점.
